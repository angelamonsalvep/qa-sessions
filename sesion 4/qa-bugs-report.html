Módulo 02 — Fundamentos
¿Qué es un bug?
Una desviación entre el comportamiento esperado del software y su comportamiento real.
⚙️
Funcional
Una función no hace lo que debería. Ej: botón que no guarda datos.
🎨
UI / UX
Problemas visuales o de usabilidad. Ej: texto desalineado, botón invisible.
⚡
Rendimiento
La app es lenta o consume recursos excesivos. Ej: loading de 15 seg.
🔒
Seguridad
Exposición de datos o acceso no autorizado. Ej: contraseña en texto plano.
🔗
Integración
Falla al comunicarse con otras partes del sistema o APIs externas.
✅
Validación
El sistema acepta datos inválidos. Ej: email sin @ aceptado.

Módulo 03 — Documentación
¿Qué es un
Bug Report?
Un documento técnico formal que comunica un defecto al equipo de desarrollo con suficiente información para que pueda ser reproducido y resuelto.
📋
Comunicación clara
Permite que QA y Dev hablen el mismo idioma técnico sin ambigüedades.
🔁
Reproducibilidad
El desarrollador puede reproducir exactamente el problema para encontrar su causa.
📊
Trazabilidad
Permite hacer seguimiento del estado del bug desde su descubrimiento hasta su cierre.
❌ Bug report deficiente
Título: No jala
Pasos: (vacío)
Evidencia: (ninguna)
Severidad: muy urgente
❌ Subjetivo · Sin pasos · Ambiguo · No reproducible
✓ Bug report profesional
Título: Checkout falla en móvil con promo activa
Pasos: 1. Abre Chrome Mobile → 2. Agrega item → 3. Aplica promo "SAVE10" → 4. Clic en Pagar
Esperado: Ir a resumen de pago
Actual: Error 422 · Pantalla se congela
Evidencia: screenshot.png · console.log adjunto
Severidad: Alta · Prioridad: Alta
✓ Claro · Reproducible · Con contexto · Con evidencia
Regla de oro: Si un desarrollador no puede reproducir tu bug con tu reporte, el bug no existe para el equipo. Tu trabajo como QA es hacer lo invisible, visible.

Módulo 08 — Calidad
Errores comunes y
buenas prácticas
Lo que separa a un QA junior de uno senior en la calidad de sus reportes.
💬
Título ambiguo
"No funciona" · "Hay un error" · "Algo está mal". Un título debe identificar el bug sin abrir el reporte.
🚶
Sin pasos de reproducción
Un reporte sin pasos es inútil. El dev no puede ver el problema. Nunca omitas los pasos.
😤
Lenguaje subjetivo o emocional
"Esto está horriblemente roto" · "Es obvio que no funciona". Los reportes son técnicos, no personales.
📸
Sin evidencia
Un screenshot, un log de consola, un video: cada pieza de evidencia acelera la resolución exponencialmente.
🔴
Todo marcado como "Crítico"
Si todo es crítico, nada es crítico. La clasificación incorrecta distorsiona la priorización del equipo.
🎯
Un bug = un reporte
Nunca mezcles múltiples bugs en un solo reporte. Mantén cada defecto aislado para facilitar el seguimiento.
🔁
Verifica la reproducibilidad antes de reportar
Reproduce el bug al menos 3 veces. Si no puedes reproducirlo consistentemente, dilo en el reporte.
📍
Incluye el entorno completo
OS, browser, versión, dispositivo, datos de prueba usados. El contexto es crítico para la reproducción.
⚖️
Separa severidad de prioridad
Evalúa el impacto técnico (severidad) y la urgencia de negocio (prioridad) de forma independiente.
🔍
Busca el mínimo reproducible
¿Cuáles son los pasos mínimos para reproducir el bug? Elimina el ruido. Menos pasos = más útil.

Módulo 10 — Cierre
Ideas clave
para recordar
El bug reporting es una habilidad técnica y comunicativa. Dominarla te hace un QA invaluable.
🎯
Un bug, un reporteAísla cada defecto en su propio documento para facilitar el seguimiento y la priorización.
🔁
Reproducibilidad es todoSi no puedes reproducirlo, no puedes reportarlo. Verifica siempre antes de documentar.
⚖️
Severidad ≠ PrioridadImpacto técnico vs urgencia de negocio. Son dimensiones independientes que trabajan juntas.
📸
Evidencia siempreScreenshot, video, logs de consola. La evidencia multiplica la velocidad de resolución.
🌐
Contexto completoOS, browser, versión, datos de prueba. El dev necesita replicar exactamente tu entorno.
📊
Sigue el ciclo de vidaNew → Assigned → Fixed → Retest → Closed. El seguimiento es responsabilidad del QA.

Un buen QA no solo encuentra bugs.

Los documenta con tanta claridad y precisión que el equipo puede resolverlos sin una sola pregunta adicional. Esa es la marca de un profesional.
